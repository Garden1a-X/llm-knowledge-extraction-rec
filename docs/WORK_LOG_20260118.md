# Work Log - 2026-01-18

## 🚨 Critical Data Leakage Bug Fix

### 问题发现

在继续MKGAT baseline实现的过程中，发现我们自己模型的分数异常高（比RecBole baselines高出~27%），经过仔细排查，发现了**3个严重的数据泄露问题**。

### 问题详情

#### 1. 图构建数据泄露（最严重⚠️⚠️⚠️）

**位置**: `src/data/graph_builder.py` + `scripts/train_model.py` + `scripts/train_model_fast.py`

**问题**:
```python
# 错误的顺序（之前的代码）
hetero_graph, cf_edge_index, stats = builder.build_hetero_graph()  # 从所有数据构建！
train_df, val_df, test_df = split_data(...)  # 后分割
```

- 异构图从**完整交互文件**（train+val+test）构建
- `_add_user_item_edges()` 添加了所有 user-item 边到图中
- `_build_cf_graph()` 从所有交互构建CF二部图
- GNN消息传递时会聚合来自test items的信息
- 用户/物品embedding会编码test set的模式

**影响**: 模型在训练时就"知道"了test set中的user-item关系，导致分数虚高。

#### 2. 测试评估未排除val items（中等⚠️）

**位置**: `src/utils/metrics.py` + 训练脚本

**问题**:
```python
# 之前的代码
excluded_items = set(test_items)
excluded_items.update(train_user_items.get(user_id, []))
# 缺少：excluded_items.update(val_user_items.get(user_id, []))
```

- uni100模式负采样时只排除了train items
- val items可能被采样为负样本
- 如果val items排名高，会挤压test positive items的排名

**影响**: 测试集指标虚高（但影响相对较小）。

#### 3. 训练负采样只排除当前split items（轻微）

**位置**: `src/data/dataset.py`

**问题**: 训练时负采样只排除当前split的items，不排除其他splits的items。

**影响**: 验证集和测试集训练时可能将train items采样为负样本，导致混合信号，但这会**降低**性能而非提高。

### 修复方案

#### Fix 1: 图构建只用训练集

**修改文件**:
- `src/data/graph_builder.py`
- `scripts/train_model.py`
- `scripts/train_model_fast.py`

**关键改动**:
```python
# 新增参数
def build_hetero_graph(self, train_inter_df: Optional[pd.DataFrame] = None):
    """
    Args:
        train_inter_df: 训练集交互数据（仅用于构建user-item边和CF图）
                       如果为None，则使用完整的inter文件（会导致数据泄露！）
    """
    # 1. 加载数据（用于构建ID映射）
    item_kg, user_kg, inter = self.load_data()

    # 2. 构建ID映射（需要用完整的inter确保覆盖所有用户和物品）
    self.build_id_mappings(item_kg, user_kg, inter)

    # 3. 使用训练集构建user-item边
    inter_for_edges = train_inter_df if train_inter_df is not None else inter
    if train_inter_df is not None:
        logger.info("  Using TRAIN-ONLY interactions for graph edges (no data leakage)")
    else:
        logger.warning("  WARNING: Using ALL interactions for graph edges (DATA LEAKAGE!)")

    self._add_user_item_edges(graph, inter_for_edges)
    cf_graph = self._build_cf_graph(inter_for_edges)
```

**训练脚本**:
```python
# 正确的顺序
# 1. 先分割数据
train_df, val_df, test_df = split_data(...)

# 2. 再构建图（只用训练集）
hetero_graph, cf_edge_index, stats = builder.build_hetero_graph(train_inter_df=train_df)
```

#### Fix 2: 测试评估排除val items

**修改文件**:
- `src/utils/metrics.py`
- `scripts/train_model.py`
- `scripts/train_model_fast.py`

**关键改动**:

# evaluate_ranking 新增参数
def evaluate_ranking(

- KGAT: NDCG@10 = 0.1209

### 经验教训

1. **先分割数据，再构建图** - 这是基本原则
2. **图构建必须只用训练集** - 任何包含test/val的边都是泄露
3. **评估时排除所有历史数据** - train + val都要排除
4. **代码审查要细致** - 特别是数据流和调用顺序
5. **异常高的分数要怀疑** - 如果结果"好得难以置信"，可能真有问题
